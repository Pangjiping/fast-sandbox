- [x] **用明确的 Create 阶段对象重构 `createOrGetSandboxCRD` 与 `createRuntimeWithFallback`。** 现状：前者接收 7 个参数并返回 5 个值，后者再次平铺传入 `sandbox`、`rankedFastlets`、`envelope`、`createdIntent` 和 `completion`；这些值实际上共同描述一个创建计划及其持久化后的状态，却在 fallback 中被分别替换和传递。`orchestrator` 已由 `Server` 持有，`requestID/createSpecHash` 也已写入 Sandbox annotations，均不应重复作为参数。建议引入有业务含义的 `plannedCreate`（Sandbox、按序候选、初始 Assignment）与 `acceptedCreate`（实际 Sandbox、允许尝试的 Runtime candidates、当前 Assignment、是否本次新建）结构；`acceptCreateIntent(ctx, plan)` 只负责创建 CRD或验证并加载同一个幂等 intent，`provisionRuntime(ctx, accepted, completion)` 负责按序尝试候选。Fallback 内再以小而明确的操作表达“生成下一 Runtime identity 并 CAS assignment”“调用一个 candidate”“仅在明确的 admission rejection 下继续”“回滚本次新建 intent”，不要继续用通用 Options struct 隐藏参数。必须保持以下错误边界：已有幂等 intent 只重试原 assignment，不能切到新的候选；只有 `RejectedBeforeSideEffects` 才允许 fallback；结果未知时保留 CRD 给 Controller 恢复；全部候选明确拒绝时仅删除本次新建的 CRD，并使用 UID precondition；CAS 冲突返回 Aborted；Fastlet 返回 `nil error` 但 response/Sandbox 为空应作为明确的协议错误处理，不能输出包含 `<nil>` 的 Unavailable。验收覆盖首次候选成功、幂等重入、顺序 fallback、assignment attempt/route generation/runtime identity 更新、CAS 冲突、模糊失败保留 intent、新 intent 全拒绝回滚、旧 intent 全拒绝不删除，以及返回 completion/Generation 不变。
- [x] **在根 `README.md` 增加简洁的 Performance 章节。** README 目前缺少能够直观展示 Fast Sandbox 性能特征的数据；建议用一张小表给出最有代表性的指标，例如 Sandbox 创建到 `RUNTIME_READY`、创建到 Overall `READY`、`ResolveEndpoint` 延迟以及稳定并发创建吞吐量，至少展示 p50/p95/p99 或清晰标注所用统计口径。每组数据必须同时注明测试日期、代码 commit、运行时与镜像、节点硬件/虚拟化环境、集群规模、是否预热、并发度和样本量，并链接到仓库内可复现的 benchmark 脚本或完整报告；不要只放缺少环境和口径的单个“最快耗时”，也不要把本地理想环境结果表述为生产 SLA。README 只保留摘要和复现入口，详细曲线、资源占用及不同场景对比放在独立 benchmark 文档中。
- [x] **将 Create completion 的默认值解析和协议转换收敛到 FastPath 入口。** 现状：`CreateSandbox` 先用 `normalizeCreateCompletion` 将外部 `UNSPECIFIED` 转成 `READY`，再把 FastPath enum 传入 `createRuntimeWithFallback`；后者又将其转换为 `fastletapi.CreateCompletion`，同时保留外部 enum 用于构造 `CreateSandboxResponse`，导致 fallback 同时依赖 FastPath API、Fastlet 协议和响应模型。建议在入口通过一个明确的解析函数一次得到“规范化后的 API completion”和对应的 Fastlet completion；Runtime provisioning/fallback 只接收 `fastletapi.CreateCompletion` 并返回 Fastlet observation，最终 FastPath response 由入口统一构造。`UNSPECIFIED => READY` 的默认语义保持不变，completion 仍只表示本次 RPC 的等待阶段，不进入 Sandbox desired state，也继续从 `CreateSpecHash` 中排除。验收覆盖未指定值默认等待 Overall Ready、显式 Runtime Ready、显式 Ready、非法 enum 拒绝，以及响应中的 completion 始终返回实际采用的规范化值。
- [x] **重构 Fastlet `CreateSandboxRequest`，消除 `Identity` 与 `SandboxSpec` 中的重复字段。** 现状：`SandboxUID/SandboxID/ClaimUID`、`RequestID`、`InstanceGeneration`、`RuntimeInstanceID`、`AssignmentAttempt`、`RouteGeneration` 和 `FastletPodUID` 在 `Identity` 与 `SandboxSpec` 中重复表达；Controller 同时填充部分重复值，Fastlet 的 `prepareCreateSpec` 又用 `Identity` 覆盖 Spec，而 validation 仅检查 `SandboxID` 冲突，其余不一致会被静默改写，形成两份权威来源。建议保留“Identity + desired Spec”的分层，但让 `SandboxIdentity` 独占 Sandbox UID、namespace/name、runtime incarnation、assignment/route generation 和 Fastlet Pod UID 等定位与 fence；`SandboxSpec` 只保留 image、resources、profiles、infra revision、command/args/env/workingDir 等运行期 desired configuration；`RequestID` 作为本次创建的幂等/观测标识移到 `CreateSandboxRequest` 顶层，`SpecGeneration`、Bindings 和 completion 继续作为请求级字段。Fastlet/Runtime Driver 若需要同时使用 identity 与 desired spec，应显式传递组合对象或构造唯一的内部 runtime input，不能再复制字段后覆盖。移除旧字段、`prepareCreateSpec` 的赋值合并及“允许 SandboxID 为空或等于 UID”的兼容校验，并同步 Controller 构造、Fastlet handler、Runtime drivers、日志 identity、测试 fixture 和文档。验收覆盖 identity fence、同名不同 UID、runtime recreate、assignment retry、route generation、请求幂等及序列化请求中每个概念只出现一次。
- [x] **删除 Fastlet Binding 请求中由 `Input` 派生的 `InputDigest`。** 当前 Controller 在 `compileActionBindings` 中根据完整 input 计算 digest 并随 `ActionBindingInput` 发送，Fastlet 的 `validateDesired` 收到后又重新计算并校验，形成业务值和派生值两份输入来源。RPC 已携带完整 opaque string，digest 只应由实际负责幂等、状态比较和 Handler invocation ID 的 Fastlet 统一计算；删除 wire `InputDigest`、Controller 侧计算与不一致校验，保留 Fastlet 内部 desired/applied digest 状态。验收应确认同一原始字符串得到稳定 digest、不同字节内容得到不同 digest，且 Controller 到 Fastlet 的请求中每个 Binding 只包含 Handler 和 input。
- [x] **收敛 Fastlet capacity 为一个权威字段。** 当前 `FastletStatus.Capacity` 与 `FastletStatus.Admission.Capacity` 重复，Registry 又同时保存 `FastletInfo.Capacity` 和 `FastletInfo.Admission.Capacity`，`ApplyHeartbeat` 先读 Admission、无值时 fallback 到顶层 Capacity，说明兼容迁移已经形成双份权威。建议仅保留 `AdmissionStatus.Capacity` 作为 Fastlet heartbeat/admission 的容量快照；Registry 和调度代码直接读取该字段或通过统一 accessor 读取，不再复制到另一个可独立变化的字段。同步删除旧 fallback、序列化字段和测试，验证容量、used/creating/running/deleting 仍来自同一时点的 admission snapshot。
- [x] **删除 `SandboxPoolStatus` 中与 `CurrentPods` 完全相同的 `TotalFastlets`。** 当前 Pool Controller 在同一分支中将二者都赋为 `currentCount`，因为现阶段一个 Fastlet Pod 就对应一个 Fastlet，两个字段没有不同语义。CRD Status 保留 `CurrentPods`、`ReadyPods`、`IdleFastlets` 和 `BusyFastlets` 即可；FastPath `PoolInfo.total_fastlets` 若仍需要对用户展示，可以在响应边界由 `CurrentPods` 映射，不应在 CRD 持久化第二份值。未来只有真正支持一个 Pod 多 Fastlet时，才基于明确计数来源重新增加独立指标。
- [x] **用单一 disposition 重构 Fastlet Create/Delete 响应，避免多个 bool 与错误 outcome 重复编码结果。** `CreateSandboxResponse` 当前同时包含 `Accepted`、`Created`、`InProgress` 和 `Error`，而 `FastletError.Outcome` 又重复表达副作用结果，协议允许构造互相矛盾的组合。Create 使用唯一的封闭 `CreateDisposition`：`CREATED`、`EXISTING`、`IN_PROGRESS`、`REJECTED_BEFORE_SIDE_EFFECTS`、`FAILED_NEEDS_CLEANUP`、`UNKNOWN`、`GENERATION_FENCED`；删除 `Accepted/Created/InProgress` 和 `FastletError.Outcome`，错误对象只保留 code/message/retryable。只有 `REJECTED_BEFORE_SIDE_EFFECTS` 允许 FastPath fallback；没有收到可解析响应的 transport failure 等价于 `UNKNOWN`。`DeleteSandboxResponse.Accepted` 和 FastPath `DeleteResponse.success` 一并删除，成功响应明确表示“删除已接受”，不承诺异步 runtime/network teardown 已完成。验收覆盖首次创建、幂等已有、创建中、明确无副作用拒绝、cleanup 失败、未知结果、generation fence 和删除幂等，禁止无效字段组合。
- [x] **消除 Fastlet Proxy Route 协议中的重复 route identity。** `PUT /v1/routes/{sandboxUID}` 当前又在 JSON body 的 `Route.SandboxUID` 携带同一 UID，服务端通过“body 为空则复制、不同则冲突”合并两份来源；Route watch `Event` 在顶层携带 `SandboxUID/RouteGeneration` 的同时，Applied/Draining 的 `Route` 中也包含相同字段。Apply 与现有 Delete/Drain 保持一致：path 参数是唯一 Sandbox UID，query 参数 `routeGeneration` 是唯一 generation，body 是不含二者的 `RouteSpec`。内部和 snapshot/watch 协议显式拆为 `RouteKey{SandboxUID, RouteGeneration}` 与 `RouteSpec`；Event 对所有类型只保留一份 key，Applied/Draining 额外携带 spec，Deleted 只携带 key。验收覆盖 path/body 不再需要一致性合并、route generation tombstone、Apply/Drain/Delete 和 snapshot/watch 重放。
- [x] **清理 Fastlet Heartbeat 中已经失去消费方或重复表达的字段。** `HeartbeatResponse.ObservedAt` 由 Fastlet 本地时钟填写，但 Registry 的 freshness/LastHeartbeat 实际使用 Controller 收到心跳的本地时间，wire 时间戳没有消费方且远端时钟也不适合作为存活权威；`FastletStatus.Images` 同样没有生产赋值，镜像库存的权威来源已经是带 epoch/revision/full/complete 语义的 `CacheSnapshot.Images`。删除这两个字段及相关 fixture，继续以 Controller receipt time 判断 heartbeat freshness、以 CacheSnapshot 判断镜像命中。当前 Heartbeat 内嵌的 `RuntimeDiagnostics` 又重复 `RuntimeReady`、`InfraRevision` 和 `InfraReady`，Controller 实际只从中读取 `RuntimeProfileHash`；将 `RuntimeProfileHash` 移入 `FastletStatus` 调度快照并从 Heartbeat 删除整个 `Diagnostics`，独立 `/runtime-diagnostics` 接口继续提供 reason/message 等人工诊断信息。
- [x] **整理 `ResolveEndpointResponse` 的 requested target 与 resolved endpoint，避免字段重叠。** 当前响应同时返回 `EndpointTarget target`、`component_name` 和 `resolved_port`：component 请求会重复 component name，port 请求可能重复 port，调用方难以区分回显输入和解析结果。删除调用方已经持有的 target 回显，响应改为嵌套 `ResolvedEndpoint{component_name, protocol, port}`；port 始终表达服务端最终路由端口，component name 仅在最终解析对象确有组件身份时出现。SDK 仍用 resolved endpoint 对原请求做一致性校验。签名 credential 中的 target claims 是跨信任边界的授权 fence，不属于应删除的重复字段，必须根据最终 resolved endpoint 生成并保留。同步更新 component/port 两类测试，保证不存在两个响应字段对同一目标给出冲突值。
- [x] **拆分内部 `RuntimeSandboxSpec`，不要继续用一个名为 Spec 的平铺结构同时表达配置、身份、调用信息和资源分配结果。** 当前 `RuntimeSandboxSpec` 匿名嵌入 desired `SandboxSpec`，又复制 `SandboxID/ClaimNamespace/ClaimName`、runtime/assignment/route fence、`RequestID` 和创建后才产生的 `Network*` 字段；随后它同时被用作 Runtime Driver 的 Ensure 输入、`runtimecontract.Metadata` 的组成部分、Containerd label/Firecracker state 的持久记录以及 BoxLite HTTP payload。虽然 Controller → Fastlet wire 已经消除了重复字段，但内部模型仍丢失了类别和权威边界，而且“Fastlet-local”注释与 BoxLite 跨进程传输的事实不符。目标模型应显式组合：`RuntimeSandboxConfig{Identity SandboxIdentity, Spec SandboxSpec}` 表达稳定运行配置，`EnsureSandboxInput{RequestID, Sandbox RuntimeSandboxConfig}` 表达一次 Ensure 调用，`RuntimeAllocation{Network ...}` 只表达 Driver 创建后返回或恢复的资源分配；不要匿名嵌入并依赖 promoted fields。统一使用 `SandboxUID/Namespace/Name`，删除内部 `SandboxID/ClaimNamespace/ClaimName` 别名；`RequestID` 不得成为稳定 Runtime identity，网络分配不得作为调用方 desired input。同步 Runtime contract、Fastlet admission/metadata、Containerd、Firecracker、BoxLite、Infra、Janitor 和测试；需要恢复的数据必须在明确的 allocation/state 结构中持久化。验收应覆盖首次 Ensure、幂等重试、同名不同 UID、runtime recreate、assignment/route fence、Fastlet/Driver 重启恢复、网络资源恢复与 BoxLite 序列化，保证每个概念只有一个权威字段且不会通过复制后覆盖来合并。

> 去重边界：不要机械删除有明确权威关系的投影。Assignment annotation 是创建与 CAS 的权威 fence，CRD Placement/Runtime/DataPlane generation 是面向用户的状态投影，并已有冲突检测；`SandboxInfo.ready` 也是组件状态的服务端派生汇总。此类字段可以共存，但必须只有一个写入权威，派生值不能反向驱动源状态。
